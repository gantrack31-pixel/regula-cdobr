# Регула

Локальный помощник по регламентам и документам для кейса ЦДОБР. Сотрудник задаёт вопрос, открывает подтверждающий пункт, собирает проект по модулю и проверяет маршрут согласования. Куратор обновляет базу без изменения кода.

В комплект включены 10 предметных источников организаторов: учебная инструкция, матрица, методические рекомендации и семь DOCX-модулей. Описание конкурса и видеопрезентация использованы для требований, но намеренно не смешаны с правилами делопроизводства в поисковой базе.

Стек: **React 19 + TypeScript + FastAPI + SQLite + Ollama / Qwen3**. Приложение работает с локальной моделью и не требует ключа облачного LLM API.

## Получить проект

```bash
git clone https://github.com/gantrack31-pixel/regula-cdobr.git
cd regula-cdobr
```

Репозиторий приватный: для клонирования нужна авторизация GitHub с доступом к нему. Включены исходники frontend и backend, Docker-конфигурация, учебные источники, тесты, документация, презентация, видео и пример DOCX. Локальные пароли, `.env`, пользовательская база и история, логи, виртуальное окружение, `node_modules` и веса моделей в Git не входят. При первом запуске база создается из `data/sources/`, зависимости устанавливаются скриптами ниже, модели загружаются отдельно.

Проверки на 24.10.2026: **95 автотестов**, **21/21 проверка Docker**, **7/7 контрольных оснований** при поиске на новой базе без готового векторного индекса. Это результаты конкретных прогонов, а не гарантия отсутствия всех ошибок; подробности и ограничения — в [отчете](docs/VALIDATION.md).

## Быстрый запуск на Windows

Требуются Python 3.12+, Node.js 22+ и, для генерации ответов, Ollama. Приложение сохраняет полезный режим поиска и цитирования при недоступной модели, явно показывая ограничение.

```powershell
# Один раз
Copy-Item .env.example .env
ollama pull qwen3:8b
ollama pull qwen3-embedding:0.6b

# Установка зависимостей, сборка UI, запуск
powershell -ExecutionPolicy Bypass -File scripts/start.ps1 -Install
```

Откройте [http://127.0.0.1:8765](http://127.0.0.1:8765). Этот адрес доступен только на компьютере с запущенным сервером и не является публичной ссылкой для жюри. В учебном режиме доступны роли сотрудника, куратора и администратора. Выбор роли в демо является демонстрационной функцией, а не механизмом корпоративной идентификации. Повторные входы с одной демо-ролью используют общий учебный аккаунт и его историю.

Если официальный реестр Ollama недоступен, `python scripts/setup_models.py` скачивает GGUF из официальных репозиториев Qwen, сверяет SHA256 и импортирует их в Ollama. Скрипт загружает только модели, не отправляет документы. Нужно примерно 7 ГБ для скачивания и дополнительное место для импорта.

На Linux/macOS: `bash scripts/start.sh`. Для разработки API: `scripts/start.ps1 -Dev`; UI в другом терминале: `cd frontend; npm run dev`. Vite работает на порту 5173 и проксирует API на 8765.

| Задача | Где выполнить |

| Вопрос своими словами, контекст диалога, точные цитаты и редакции | Помощник |
| Просмотр исходного документа и релевантного пункта | Панель источников ответа |
| История диалогов каждого пользователя | Помощник |
| Заполнение семи предоставленных модулей, помощь диалогом, DOCX | Документы |
| Проверка полноты, дат, условных пунктов и служебных зон | Редактор проекта |
| Проверка загруженного DOCX/PDF/текста | Проверка |
| Объяснимый маршрут по матрице и условиям | Маршрут |
| Загрузка новой редакции, сравнение и активация | База знаний, роль куратора |

В демо доступны примеры для трёх содержательных частей кейса: инструкция, модуль и матрица визирования. Проект документа остаётся черновиком: приложение не подписывает его и не присваивает официальный регистрационный номер.

## Новый шаблон за минуту

1. Откройте демо под куратором.
2. В «Базе знаний» загрузите `demo/new-module.txt`, выберите категорию «Модуль».
3. Активируйте созданную редакцию. До активации она не участвует в обычных ответах.
4. Перейдите в «Документы», выберите новый модуль и заполните обнаруженные поля.
5. Скачайте DOCX. Для новых шаблонов рекомендуем DOCX с именованными полями `{{subject}}`, `{{author}}`, `{{body}}`.

Семь исходных модулей имеют отдельные схемы и правила заполнения. Произвольный файл с подчёркиваниями без именованных полей не следует считать автоматически понятным конструктору.

Новые инструкции и редакции становятся источниками поиска после активации. Загрузка новой матрицы не переписывает правила маршрутизации и автоматической проверки: для изменения этих правил требуется обновить код и тесты.

## Модели и поиск

- Qwen3 8B через Ollama формулирует ответы и извлекает значения полей из сообщения.
- Qwen3 Embedding 0.6B строит векторы для смыслового поиска.
- Поиск по словам использует BM25 и русский стемминг. Смысловой поиск дополняет его после построения индекса. Без векторов работает BM25.
- Источники ограничиваются правами пользователя и выбранной редакцией до поиска.
- Ответ принимает ссылки только на реально найденные фрагменты. Наличие корректной ссылки не является математической гарантией правильности интерпретации модели.
- При недоступной модели интерфейс показывает найденные выдержки. Он не выдаёт их за сгенерированную консультацию.

Локальный API не требует внешних LLM-ключей. Индексацию векторов можно запустить запросом `POST /api/sources/index` под куратором. Она работает в фоне и не блокирует запуск приложения.

## Docker

```bash
docker compose up --build -d
docker compose logs -f app
```

По умолчанию порт опубликован только на loopback. Контейнер подключается к Ollama на хосте через `host.docker.internal`. Если Ollama слушает исключительно 127.0.0.1 и недоступен контейнеру, настройте его на интерфейс Docker с ограничением сетевого доступа либо используйте нативный запуск. Не открывайте API Ollama в интернет. Данные сохраняются в томе `regula-runtime`.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pytest tests -q
cd frontend
npm run build
```

Тесты проверяют предметные правила, экспорт документов, версии, ограничение доступа, принадлежность пользовательских объектов, загрузку файлов и HTTP-защиты. Отдельный прогон реальных вопросов модели описан в `docs/VALIDATION.md`. Фактические результаты и ограничения следует смотреть там, а не считать наличие тестового файла свидетельством его прохождения.

## Границы прототипа

Учебные документы не являются действующими актами Банка России. Инструкция содержит условную дату начала применения 01.11.2026; обычный режим использует явно активированную учебную редакцию. Режим «на дату» учитывает даты применения.

Проверка проектов покрывает реализованные структурные и предметные правила, но не заменяет лингвистическую экспертизу, юридическое согласование, проверку полномочий и подпись. Для сканов без текстового слоя требуется предварительное OCR. Реальной интеграции с ИИС ДО, корпоративным SSO и электронной подписью в прототипе нет.

Перед внедрением: отключить `DEMO_MODE`, задать пароль администратора, подключить SSO и корпоративную политику доступа, HTTPS, защищённое хранение и резервирование, мониторинг, антивирусную проверку загрузок, пилотный набор вопросов экспертов. См. `docs/SECURITY.md`.

Локальное управление сотрудниками и кураторами без демо-выбора ролей: [учётные записи](docs/ACCOUNTS.md). Команды запрашивают пароль скрыто, отключение пользователя и смена пароля отзывают его сессии. Для существующего администратора используйте `set-password`, изменение `ADMIN_PASSWORD` в окружении действует только при первоначальном создании.

Для полностью контейнерного варианта с отдельным локальным Ollama: `docker compose -f compose.yaml -f compose.ollama.yaml up --build -d`. Затем загрузите модели командами из комментариев `compose.ollama.yaml`. По умолчанию модель работает на CPU; GPU включается настройкой NVIDIA Container Toolkit на целевом сервере. Порт Ollama наружу не публикуется.
