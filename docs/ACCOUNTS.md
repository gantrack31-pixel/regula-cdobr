# Локальные учётные записи

CLI запускается на сервере приложения с правом записи в `data/runtime/app.sqlite3`. Он предназначен для администратора системы и не является сетевым API. Пароли вводятся дважды через скрытый интерактивный ввод; аргументов командной строки для пароля нет.

В PowerShell из каталога проекта:

```powershell
.venv\Scripts\python.exe scripts/manage_users.py list
.venv\Scripts\python.exe scripts/manage_users.py create anna --name "Анна Морозова" --role employee
.venv\Scripts\python.exe scripts/manage_users.py create curator --name "Михаил Орлов" --role curator
.venv\Scripts\python.exe scripts/manage_users.py set-password admin
.venv\Scripts\python.exe scripts/manage_users.py disable anna
.venv\Scripts\python.exe scripts/manage_users.py enable anna
```

В Linux используйте `.venv/bin/python`. Для нестандартного расположения базы перед командой передайте `--database /absolute/path/app.sqlite3`. CLI также учитывает переменную окружения `DATA_DIR`; файл `.env` он самостоятельно не читает. Для контейнера выполните команду через интерактивный терминал, например `docker compose exec app python scripts/manage_users.py list`.

Допустимые роли: `employee`, `curator`, `admin`. Логин содержит 3–100 латинских букв, цифр и символов `_.@-`, начинается с буквы или цифры. Префикс `demo-` зарезервирован. Пароль содержит 12–500 символов. Команда `list` не показывает пароли и их хеши.

Отключение учётной записи и смена пароля немедленно отзывают все её сессии. Повторное включение не восстанавливает старые токены. Отключённая запись сохраняет собственные диалоги и черновики, но не может войти в приложение. Административные действия фиксируются в журнале без паролей.

## Первый запуск без демонстрационных пользователей

На пустой базе можно создать администратора через CLI:

```powershell
.venv\Scripts\python.exe scripts/manage_users.py create admin --name "Администратор" --role admin
```

Затем установите `DEMO_MODE=0` и запустите приложение. Альтернативно первый запуск приложения создаёт администратора из `ADMIN_PASSWORD`, если этой записи ещё нет. Настройка сетевого доступа по-прежнему требует HTTPS и корректных Host/Origin.

## Переход после демонстрации

`ADMIN_PASSWORD` не меняет пароль существующей записи `admin`. После первого демозапуска случайный пароль уже создан; установка новой переменной окружения его не заменит. Выполните `set-password admin`, создайте нужные персональные записи, установите `DEMO_MODE=0` и перезапустите приложение. Ранее выданные демонстрационные сессии будут отвергнуты приложением.

Для восстановления доступа используйте этот локальный CLI с правами администратора хоста. Не отключайте единственную административную запись без доступного пути восстановления. SSO и назначение ролей из корпоративного каталога остаются отдельным этапом внедрения.
