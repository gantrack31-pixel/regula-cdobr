## Что именно делает модель

Qwen3:8b не дообучалась. Веса модели прежние. Изменены поиск, прикладные ограничения и взаимодействие с пользователем.

Из 30 прежних вопросов **23** получили точную норму через каталог проверяемых процедур, **3** — выбранные моделью и проверенные выдержки, **4** — отказ из-за отсутствия источника, прав или подходящей редакции. В дополнительной выборке распределение — **6 / 3 / 3**. Поэтому результаты нельзя называть «100% точностью нейросети».

Каталог хранит соответствие темы и пункта, но не численные ответы. Текст каждый раз берётся из разрешённой редакции источника. При отсутствии пункта или несовпадении его сигнатуры готовый ответ по этому правилу не создаётся. Для остальных вопросов модель возвращает идентификатор и дословную выдержку. Программа проверяет текст, расставляет ссылки, раскрывает полную строку матрицы и продолжения пункта на следующих страницах. Свободно сгенерированное численное правило не показывается.

При заполнении явные даты, роли и факты сначала извлекаются программно. Модель разбирает оставшиеся поля, для которых есть предметный признак в просьбе. Значение проходит проверку типа, цитаты и назначения поля. Подписант не становится участником группы или контролёром автоматически. Неизвестные сведения остаются пустыми, противоречивые значения предлагается уточнить. Частичные изменения массива участников требуют ручной проверки: автоматическое объединение составов не выполняется.

## Устойчивость и интерфейс

`POST /drafts/{id}/suggest` не меняет проект. Пользователь видит старое и предлагаемое значение и цитату, выбирает поля и применяет их. `PATCH` передаёт номер ревизии; SQLite сравнивает его и сохраняет результат в одной транзакции. Устаревшее изменение получает 409. Старый `/assist` сохранён для совместимости, но его значения не считаются проверенными человеком.

Добавлены подсказки недостающих сведений, отмена последнего применения, счётчик ожидания, защита ухода с несохранёнными сведениями, понятные статусы и мобильные карточки. Сохранение, подтверждение и экспорт показывают разные результаты. Подтверждение человеком не является юридической экспертизой.

Лимит тяжёлых операций — два одновременно в одном процессе. Проверено получение 429 и сохранение доступности health. Ограничение частоты возвращает Retry-After. В быстром регрессионном прогоне достигнут лимит 20 вопросов в минуту; сценарий подождал 42 секунды и успешно продолжил. Это ожидаемое ограничение, а не падение.

Первый диагностический запуск обнаружил замедление при одновременной работе генерации и эмбеддингов в видеопамяти занятого Windows-десктопа. Для этой машины в локальном `.env` задано `EMBEDDING_NUM_GPU=0`. Qwen3:8b остаётся на GPU, небольшая модель поиска работает на CPU. Конфигурация персонального компьютера в репозиторий не включена; параметр описан в `.env.example`. Память зависит от контекста и числа одновременно загруженных моделей — см. [официальное описание Ollama](https://github.com/ollama/ollama/blob/main/docs/faq.mdx).

Медиана времени ответа без ожидания Retry-After — **0,565 с** на прежних вопросах и **0,565 с** на дополнительных. Три запроса с генерацией в каждом наборе заняли до **3,36 с** целиком. Медиана извлечения реквизитов — **0,041 с / 0,032 с**: большая часть фактов обработана без генерации. Это измерения Ryzen 5950X / RTX 3080 12 ГБ, не обещание производительности на другом оборудовании.

При визуальной проверке устранены повтор подразделения в должности и разрыв блока подписи по страницам. Наименования ИС заключены в кавычки, перечень передаваемого имущества выделен скобками. Отсутствующие реквизиты отмечены явно на русском. Блоки ЭП, даты, номера и учебная зона герба сохранены из модулей. LibreOffice отсутствует в этом окружении: packaged renderer диагностировал отсутствие soffice, поэтому использован установленный Word и Poppler.

## Воспроизведение и границы

```powershell
python -m pytest -q
npm.cmd run build --prefix frontend
python -X utf8 scripts/evaluate_quality.py --output output/my-quality/main.json
python -X utf8 scripts/evaluate_holdout.py --output output/my-quality/holdout.json
```

Живые сценарии используют настоящий Ollama и отдельную копию базы знаний, без копирования учетных записей, сессий и истории. Файл результата нельзя перезаписать случайно: для следующего прогона нужен новый путь. Исходные журналы текущей проверки находятся локально в `output/quality-fixed/`; в Git опубликована компактная сводка `docs/quality-results.json`. GitHub Actions запускает автотесты и сборку на push и pull request, без модели и без секретов.

Сохраняются границы: произвольная формулировка может потребовать уточнения; точная цитата не доказывает смысловую полноту ответа; нет автоматической проверки полномочий по отсутствующим регламентам. OCR, корпоративный SSO, интеграция ИИС ДО и действительная ЭП не реализованы. Презентация и прежний ролик показывают предыдущую версию интерфейса. Отдельный публичный адрес для жюри по-прежнему требует развёртывания; текущий экземпляр доступен локально. Новая повторная проверка не заменяет нагрузочные испытания или независимый аудит безопасности.
