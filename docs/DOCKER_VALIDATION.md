## Изоляция проверки

Использован отдельный контейнер `regula-qa`, порт `127.0.0.1:8766`, volume `regula-qa-data`. Запущенный ранее сторонний контейнер на порту 8000 и нативный сервер Регулы на 8765 не изменялись.

```powershell
docker build -t regula-hackathon:local .
docker run -d --name regula-qa --label regula.qa=true --publish 127.0.0.1:8766:8000 --volume regula-qa-data:/app/data/runtime --env DEMO_MODE=1 --env OLLAMA_BASE_URL=http://host.docker.internal:11434 --add-host host.docker.internal:host-gateway --security-opt no-new-privileges:true --cap-drop ALL regula-hackathon:local
.venv\Scripts\python.exe -X utf8 scripts/docker_smoke.py
docker stop regula-qa
```

Повторный запуск контейнера с тем же именем требует сначала остановить и удалить только прежний контейнер `regula-qa`; volume можно сохранить для проверки устойчивости данных. Сценарий `scripts/docker_smoke.py` ожидает готовность сервера до 45 секунд, создаёт учебные диалоги и черновики в указанном QA-контуре и сохраняет результат в `output/docker-validation.json`. Пароли и cookie в отчёт не попадают. Сценарий повторяет 14 HTTP-проверок; полный итоговый отчёт дополнен семью проверками окружения, отказоустойчивости и сохранности данных.

Вопрос о последовательности визирования нашёл полный п. 10.6 на страницах 42 и 43, ответ перечислил все восемь позиций. Вопрос вне базы получил `insufficient` без цитат. Результаты: `output/evaluation-docker.json`. Это небольшой набор контрольных вопросов, не доказательство смысловой точности любого ответа.

Все остальные 343 фрагмента совпадают дословно, включая документ, пункт, страницу и контекст таблиц. Свежая индексация с `pypdf 6.21.2` подтвердила тот же результат; содержательные правила не потеряны. Подробное сравнение: `output/docker-corpus-comparison.json`.
